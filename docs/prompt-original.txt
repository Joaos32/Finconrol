Quero que você atue como um engenheiro de software Full Stack sênior e inicie a construção de uma aplicação chamada **FinControl**, um sistema moderno de gestão financeira pessoal.

O projeto será usado como portfólio profissional, portanto não quero apenas um CRUD funcional. Quero uma aplicação com arquitetura organizada, boas práticas, segurança, testes, documentação e código com padrão próximo de produção.

## 1. OBJETIVO DO PROJETO

O FinControl será uma plataforma onde o usuário poderá:

- criar uma conta;
- realizar login;
- cadastrar contas financeiras;
- cadastrar categorias;
- registrar receitas;
- registrar despesas;
- visualizar saldo;
- acompanhar receitas e despesas;
- visualizar um dashboard financeiro;
- consultar histórico de transações.

Nesta primeira etapa, NÃO implemente:

- cartão de crédito;
- parcelamentos;
- despesas recorrentes;
- metas financeiras;
- RabbitMQ;
- Redis;
- IA;
- integração bancária;
- AWS;
- microsserviços.

Esses recursos serão adicionados posteriormente.

O objetivo agora é criar um MVP muito bem estruturado e preparado para evolução.

# 6. REGRA DE SALDO

Não quero que o saldo atual seja simplesmente armazenado e atualizado sem necessidade.

Calcule o saldo utilizando:

saldo atual = saldo inicial + receitas - despesas

O saldo deve ser calculado com base nas transações da conta.

Crie métodos eficientes no repository para realizar agregações no banco sempre que possível.

Evite carregar todas as transações na memória apenas para somar valores.

---

# 7. AUTENTICAÇÃO

Implementar autenticação utilizando:

Spring Security + JWT.

Endpoints:

POST /api/auth/register

Body:

{
  "name": "João Silva",
  "email": "joao@email.com",
  "password": "Senha123!"
}

POST /api/auth/login

Body:

{
  "email": "joao@email.com",
  "password": "Senha123!"
}

Resposta:

{
  "accessToken": "...",
  "tokenType": "Bearer"
}

Inicialmente pode ser utilizado apenas access token.

Estruture o código de forma que refresh token possa ser adicionado posteriormente.

JWT deve conter apenas informações mínimas necessárias.

Nunca colocar dados sensíveis no token.

---

# 8. SEGURANÇA

Essa parte é extremamente importante.

Todas as rotas financeiras devem exigir autenticação.

Exemplo:

/api/accounts
/api/categories
/api/transactions
/api/dashboard

Não aceitar userId enviado pelo frontend para definir proprietário dos dados.

O usuário deve sempre ser identificado através do token JWT.

Exemplo errado:

POST /transactions

{
  "userId": 10
}

Não fazer isso.

O backend deve identificar o usuário autenticado através do SecurityContext.

Todas as queries devem levar o usuário autenticado em consideração.

Nunca usar:

findById(id)

quando existir possibilidade de consultar registros de outro usuário.

Preferir algo equivalente a:

findByIdAndUserId(...)

para evitar IDOR.

# 11. TRATAMENTO DE ERROS

Criar tratamento global utilizando:

@RestControllerAdvice

Padronizar erros.

Exemplo:

{
  "timestamp": "2026-09-28T15:30:00",
  "status": 400,
  "error": "Bad Request",
  "message": "Categoria incompatível com o tipo da transação",
  "path": "/api/transactions"
}

Tratar pelo menos:

- recurso não encontrado;
- validação;
- conflito;
- acesso negado;
- credenciais inválidas;
- erro de regra de negócio.

Evitar retornar stacktrace para o frontend.
